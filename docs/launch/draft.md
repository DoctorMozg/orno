1. **"Plan before you spend, replay without spending: orno is `terraform plan` for agent pipelines."**
   Frames the pairing directly. "Plan/replay" is the unique surface; the comparison anchors the mental model in something the audience already runs in CI.

2. **"Stop guessing what your agent will do. Start replaying what it did."**
   More emotional, lower information density. Works as a tweet; reads thinner as a blog headline.

3. **"orno: every agent run is auditable before it spends a token, and reproducible after."**
   States the value proposition cleanly. Slightly long, but the two clauses mirror the hero pair (`plan` ↔ before, `replay` ↔ after).

**Pick:** Option 1. It names the differentiator (`plan`/`replay`), uses a comparator the CI/SRE audience already trusts (`terraform plan`), and reads as a thesis statement, not a slogan. Options 2 and 3 are fallbacks for shorter-form channels (Twitter, Hacker News submission title).

## Opening

Every team that has put an LLM agent in CI has hit the same two walls. The first is spend: a pipeline merges, runs in production, and burns ten times what anyone expected because nobody had a way to tell — short of running it — what it was *going to* do. The second is debugging: a run failed last Thursday, the logs are gone, the model has been swapped, and nothing about the failure can be reproduced.

orno is built around a single answer to both: `orno run` always knows what it is going to do before you spend a token, and what it did is always replayable after the fact. `orno plan <pipeline.yaml>` walks the DAG, surfaces every declared effect, sums the worst-case budget across every agent, and prints the result as NDJSON in milliseconds — no LLM call, no tool execution, no network. Pair it with a recorded run: `orno run --record-bundle run.ndjson` captures every LLM request and every tool result, and `orno replay run.ndjson` re-executes the pipeline byte-for-byte from that bundle, on any machine, with no API key. Audit before spend, reproduce after.

## The five dimensions

Underneath the hero surface is the contract that makes the recording lossless. Every `agent` node in an orno pipeline runs under five runtime-enforced bounds: **iteration** (`max_iterations` is mandatory; overrun terminates the node), **tool surface** (only tools listed in `allowed_tools` are callable; an unknown tool name is a terminal event, not a fallback), **effects** (`allow_mutations`, `allow_network`, and domain allow/blocklists gate every tool by its declared effect class), **resources** (`max_total_tokens` and `max_tool_calls` are hard ceilings, not soft budgets), and **non-determinism** (every LLM request and every tool call is recorded; `orno replay` reproduces the run bit-for-bit). These are not prompt instructions or convention. They are checks at the executor boundary, and the loop has exactly two outcomes per iteration: pass the contract and continue, or fail it and stop.

## Who it's for

orno is for the team that already has an agent in CI — or wants one — and needs the run to be reviewable in a pull request, billable on a known budget, and reproducible during an incident. If the agent writes code, opens issues, hits a third-party API, or delegates to subagents, the team's auditing surface is currently a wall of unstructured logs and a vendor invoice that arrives at the end of the month. orno replaces both with a typed event log, a static plan, and a deterministic replay tape — the same artifacts a security review, a finance review, and a postmortem all want, generated by the runner instead of by hand.

## Call to action

Pick an example and run it:

```
git clone https://github.com/drmozg/orno
cd orno
ORNO_TEST_LLM_TRANSPORT=dummy cargo run -p orno-cli -- plan examples/hello.yaml
```

Then point it at your own pipeline. `examples/pr-review.yaml`, `examples/release-notes.yaml`, and `examples/flaky-test-triage.yaml` are the closest to production shapes. File issues, request features, and tell us which builtin tool you wish was already in the box at [github.com/drmozg/orno](https://github.com/drmozg/orno).
